# Физические задания и машины-связные

Документ разделяет текущую реализацию и целевой дизайн системы заданий. Задание
не является записью в журнале: оно существует как физический предмет в мире.

## Основной цикл

1. На части POI стоит неподвижная машина-связной.
2. В её восьмиячеечном багажнике лежат четыре случайных задания из общего каталога.
3. Каждый предмет одновременно является грузом и заданием; его название объясняет
   условие.
4. Игрок может брать, осматривать, ронять и возвращать предметы без принятия
   абстрактного контракта.
5. В багажник одной обычной машины помещается не больше одного предмета-задания.
6. Груз можно держать в руках, оставить на земле или переложить в другую машину.
7. Его принимает багажник любой машины-связного, расположенной дальше по дороге,
   чем источник.
8. Приезд без предмета ничего не завершает. Возврат источнику награды не даёт.
9. При сдаче груз атомарно превращается в подписанный конверт с наклейкой в той же
   ячейке.
10. Конверт можно забрать сразу, оставить у получателя, переносить, хранить и
    потратить на любую машину.

Глобального `activeContract`, списка принятых заданий и кнопки отказа нет. Если
игрок раскидал предложения по земле, они просто продолжают существовать там как
предметы. Ограничение «одно задание» обеспечивается багажником перевозящей машины,
а не состоянием игрока.

## Статус реализации

Работает вертикальный срез `посылка → конверт → звезда` и система типизированных
заданий: реестр видов, собственные условия с реальным влиянием на игру и отдельная
награда-наклейка у каждого вида. Машины-связные, физическое перемещение предмета,
ограничение одной посылки на обычный багажник, сдача следующему связному, защита от
повторной награды и сохранение этих данных работают.

Реализованы виды 1–5, 6, 7, 8–10, 14–20 (см. каталог). Оставшиеся виды (11, 12, 13) —
целевой дизайн ниже: они требуют подсистем, которые появляются отдельной волной
(шины, ворота).

## Машина-связной

Машина-связной — отдельная статическая сущность, а не урезанный `Vehicle`:

- стабильный ID `courier:<sequenceIndex>`, где индекс монотонно растёт вдоль дороги;
- случайная детерминированная модель из каталога автомобилей;
- общий узнаваемый courier shader при разных моделях и цветовых палитрах;
- обычные стёкла, колёса и свет; эффект применяется только к окрашенным панелям;
- нельзя сесть, завести, заправить, чинить, разобрать, толкать или буксировать;
- единственное взаимодействие — багажник из восьми ячеек;
- четыре постоянных предложения и минимум четыре свободные ячейки;
- предложения не обновляются и не используются для бесконечного фарма.
- машина ставится на обращённом к дороге краю POI, в 9,5 м от оси дороги, чтобы
  оставаться заметной из проезжающей машины и не прятаться за строениями;

Связные появляются процедурно и детерминированно на гарантированных POI через
6–12 км. Чистый независимый шанс не используется, поэтому длинная случайная пустота
не блокирует сдачу.

ID связного возрастает по направлению дороги. Предмет от связного `i` принимается
любым связным `j`, если `j > i`. Конкретный адрес и расстояние на этикетке не нужны.
Пропущенная машина не проваливает задание.

## Предмет-задание

Базовая форма:

```ts
interface ContractCargoItem {
  readonly type: 'contract_cargo';
  readonly id: string;
  readonly sourceCourierIndex: number;
  readonly contractKind: ContractKind;   // вид 1..20
  readonly cargoName: string;
  readonly rewardStickerKind: StickerKind; // обычная награда (по seed задания)
  readonly generatedSeed: number;
  readonly massKg?: number;              // груз тяжелее 12 кг (тяжёлый ящик)
  progress: ContractProgress;            // состояние условия, живёт на предмете
}

interface ContractProgress {
  started: boolean;      // груз впервые покинул связного-источника
  startedAtS: number;    // playedSeconds этого момента
  deadlineS: number;     // абсолютный мягкий срок, 0 если нет
  softDeadlineS: number; // длина срока, взятая из seed при генерации
  condition: number;     // 1..0, качество (хрупкий радиоприёмник)
  heat: number;          // накопленный нагрев, градусо-секунды (термобокс)
  exposureS: number;     // секунды под солнцем (ночной курьер)
  violated: boolean;     // особая награда потеряна, доставка всё равно платит
  late: boolean;         // мягкий срок прошёл
  statusText: string;    // короткий статус в названии предмета, '' если нет
}
```

Прогресс хранится прямо на предмете: он едет с грузом через все четыре
местоположения и через save/load, а `itemLabel` читает его без доступа к миру,
поэтому багажник, руки и подсказка всегда показывают живое состояние
(`fragile radio · 82%`, `urgent film · 15:56 left`). Вид награды `statusText`
пишет только runtime контрактов.

Предмет может находиться только в одном месте:

- в багажнике связного;
- в `PlayerState.carried`;
- в `CarState.storage`;
- в `WorldState.looseItems`.

Контракт не исчезает при переносе или падении. Другой автомобиль может продолжить
поездку, если игрок физически переложил груз в его багажник. Обычный автомобиль
отказывается принимать второй `contract_cargo`, но продолжает принимать обычные
предметы.

Сдача выполняется одной транзакцией:

```text
contract_cargo в руках → sticker_envelope в выбранной ячейке связного
```

Исходный предмет после успешной сдачи не существует. Повторно получить награду по
тому же ID нельзя.

## Система видов заданий

Вид — это модуль в `src/contracts/kinds/`, зарегистрированный в `registry.ts` одной
строкой. Добавление вида не требует правки других видов: интерфейс
`ContractKindDef` задаёт всё, что вид умеет.

```ts
interface ContractKindDef {
  kind: ContractKind;
  weight: number;                    // шанс выпадения среди предложений
  offerNames: readonly string[];
  signatureSticker: StickerKind | null; // null = только seed-random награда
  initialProgress: (seed, offer: ContractOfferContext) => ContractProgress;
  massKg?: (seed: number) => number; // груз тяжелее 12 кг
  acceptRefusal?: (item, probe) => string | null;      // probe: мир у получателя
  step: (progress, ctx) => void;     // тик, меняет progress на месте
  conditionMet: (progress, ctx) => boolean; // условие выполнено при сдаче
  onDelivered?: (item, probe, delivery) => DeliveryEffect | null; // побочный эффект
}
```

- `src/contracts/types.ts` — id видов, `ContractProgress`, `DeliveryProbe`,
  `DeliveryEffect`, контексты тика и сдачи, ночной интервал (20:00–06:00).
- `src/contracts/offers.ts` — генерация четырёх предложений связного; вес посылки 4
  против 1 у каждого особого вида, так что посылка остаётся обычной.
- `src/contracts/runtime.ts` — обход предметов в четырёх местах, определение
  перевозящей машины, старт часов при первом уходе от источника, вызов `step`.
  Запускается из фиксированного шага (`main.ts`), сразу после физики; телеметрия
  машины — долговечные числа из `CarState` и живые удары/опрокидывание из
  `Vehicle`. Заполнение бака видно как рост топлива между тиками.
- `src/contracts/registry.ts` — реестр и функции для сдачи: `contractAcceptRefusal`
  (причина отказа или null), `contractRewardSticker` (подписная наклейка при
  выполненном условии, иначе обычная), `contractDeliveryEffect` и `isContractKind`.
- `src/contracts/world.ts` — собственные объекты видов (прицеп, машина) и их
  спавн; см. ниже.

### Проба мира при сдаче

Вид, чьё условие живёт в мире снаружи груза (прицеп, машина, деталь), читает его
через `DeliveryProbe`: абсолютные x/z принимающего связного, `courierCells`,
`carried`, `trailerPosition(id)` (живое тело, если прицеп материализован, иначе
сохранённая поза), `car(id)` и `drivingCarId`. Пробу собирает `interaction.ts` и
передаёт в ОБЕ точки — подсказку при прицеливании и коммит по F, поэтому фраза на
экране и то, что делает F, читают один мир в один момент. `acceptRefusal(item, probe)`
вызывается после базового правила (связной не подписывает свой груз и груз из
дальних связных).

### Побочный эффект сдачи

`onDelivered` возвращает `DeliveryEffect`: `deltas` (`trailer_remove`, `car_remove`),
`consumeCourierItems` и `consumeCarried`. Порядок один и тот же всегда: сначала
`courier_storage` (конверт + `consumedItemId` + `completedContractId` ОДНИМ
применением), затем `deltas`, затем правки рюкзака. completed ID записан первым
применением, поэтому обрыв между половинами не может заплатить дважды; предметы,
уходящие из ячеек связного, вынимаются тем же массивом `cells`, что и конверт.

### Расширения тика

- `ContractTickContext.item` — сам груз: id мирового объекта вида выводится из
  `generatedSeed`, а seed лежит на предмете, не в прогрессе.
- `ContractCarTelemetry` дополнена `absoluteX/Z`, `onRoad` (хотя бы одно нагруженное
  колесо на асфальте — по живым поверхностям колёс) и полями прицепа перевозящей
  машины (`trailerId`, `trailerImpactMps`, `trailerUpsideDown`).
- `ContractTickInput.onContractItem(item, place, carId)` — хук на каждый живой груз,
  через который `main.ts` вызывает `ensureContractWorldObjects`, ведёт учёт машин с
  грузом «лысых покрышек» и собирает видимые последовательности ворот.
- `ContractTickInput/Context.gatesFor(item)` — последовательность ворот видов 12/13,
  строящаяся в `main.ts` из seed и геометрии дороги (`contracts/gates.ts`).

### Объекты мира у вида

Вид может владеть объектом в мире. `contracts/world.ts` называет его по seed
предложения (`contract-trailer:<seed>`, `contract-car:<seed>`), поэтому объект один
и тот же в сессии, в сейве и после загрузки, не требуя отдельного поля. Объект
появляется рядом со связным-ИСТОЧНИКОМ в момент, когда груз впервые покидает его
багажник (то есть при взятии), и защищён обычной проверкой существования: id уже в
состоянии — второй объект не появится. После сдачи груза больше нет, и создавать
заново нечего; сейв, где объект уже удалён, не может его воскресить.

Условия отслеживаются, пока груз едет: в багажнике машины, в руках или на земле.
Хрупкий груз теряет состояние от ударов и опрокидывания перевозящей машины и от
падения на землю. Награда никогда не теряется целиком: провал условия лишь меняет
подписную наклейку на обычную.

### Реализованные волной 2 виды

- **6 прицеп с оборудованием** (`kinds/trailerEquipment.ts`): нагруженный прицеп и
  его документы приезжают вместе, сдача принимает прицеп в 25 м от связного и
  расходует его. Подпись — если прицеп не получил тяжёлого удара и не опрокинулся.
- **7 негабарит** (`kinds/oversize.ts`): на прицепе 5–6 м трубы или балки, выходящие
  за 2,8-метровую платформу. У груза настоящий коллайдер и меш (`TrailerState.load`,
  `vehicle/trailer.ts`), масса идёт обычным путём `cargoKg`. Условие — довезти груз
  нетронутым (тот же порог удара ниже, чем у 6, плюс проверка опрокидывания).
- **18 перегон автомобиля** (`kinds/carTransfer.ts`): машина порождается у связного-
  источника, сдать — поставить её в 20 м от связного и выйти из неё. Сдача
  расходует машину, поэтому багажник должен быть пуст. Подпись — если кузов пришёл
  без тяжёлых царапин (`CarState.scratches` ≤ 0.45).
- **19 заказ на запчасть** (`kinds/partOrder.ts`): записка называет вариант из тех,
  что реально лежат у POI и в разбитых машинах (пять видов капота), а связной
  принимает её только вместе с этой деталью — в своих ячейках или в руках. Подпись —
  если деталь чистая (rust ≤ 0.25, dirt ≤ 0.5); погнутая идёт по обычной награде.
- **11 лысые покрышки** (`kinds/baldTyres.ts`): пока ящик едет в багажнике, машина
  держится на компаунде `bald` (`Vehicle.setEnforcedTyreCompound`). Форс ставят и
  снимают заново каждый тик: пересозданная машина стартует свободной, а клавиша
  смены покрышек при активном форсе отказывает и объясняет тост. Подпись — без
  тяжёлого удара (> 4 м/с) и без опрокидывания за всю поездку.
- **12 песчаный маршрут** и **13 пустынный слалом** (`kinds/sandRoute.ts`,
  `kinds/desertSlalom.ts`): последовательность ворот, чистая функция seed и дороги
  (`contracts/gates.ts`), рисуется `world/gates.ts` (столбы с флажками, одна общая
  пара материалов, якоря программ компилируются на загрузке). Засчитывается только
  СЛЕДУЮЩИЕ ворота — порядок обязателен, пропущенные можно перепройти. Прохождение
  ворот = отрезок пути машины между тиками пересекает створ в направлении движения
  и в пределах столбов. Прогресс — `gatesPassed` и таймер слома в `ContractProgress`.
  Подпись 12 — все ворота по порядку; 13 — все ворота по порядку, в лимит времени
  (18–32 с) и с возвращением на асфальт (`onRoad`).


## Фотографическое поручение

Содержимое JPEG не анализируется. В момент затвора игра один раз проверяет
семантическую сцену и записывает доказательство на сам предмет-фотографию:

```ts
interface PhotoEvidence {
  readonly subjects: string[];      // стабильные id попавших в кадр объектов
  readonly subjectsClose: string[]; // подмножество, снятое вплотную
  readonly roadS: number;
  readonly timeOfDay: number;
  readonly playedS: number;         // playedSeconds в момент затвора
  readonly cameraPosition: Vec3;
  readonly cameraDirection: Vec3;
}
```

- Реестр объектов (`contracts/photosubjects.ts`) — чистый читатель: монументы и
  артефакты (`monumentsBetween`), POI и связные (`poisBetween`, `couriersBetween`),
  миражи (расписание плюс текущий кадр рендера). Id стабильны: `monument:<s>`,
  `poi:<index>`, `courier:<index>`, `mirage:<индекс встречи>`.
- Проверка кадра: `THREE.Frustum` из камеры, сфера объекта, минимальная доля кадра
  (радиус/дистанция, делённые на `tan(fov/2)`; 0.05 — обычный порог), максимум
  дистанции и луч окклюзии через физику. Ставка выше порога попадает и в
  `subjectsClose`. Мираж считается только когда он реально виден в кадре (opacity
  выше порога) и днём.
- Поручение (вид 20, `kinds/photoErrand.ts`) называет один объект, выбранный из seed
  среди тех, что стоят на дороге между связным-источником и тремя связными впереди
  (id и название лежат в `progress.subjectId` / `progress.statusText`).
- Сдача принимает только фотографию, в доказательстве которой есть этот id, — в
  рюкзаке или в ячейках связного; фотография расходуется вместе с запиской.
  Подпись (`sunset`) — если снимок сделан ПОСЛЕ старта поручения (`playedS` против
  `progress.startedAtS`) и снят вплотную (`subjectsClose`).

Это игровая проверка момента экспозиции, а не компьютерное зрение.

## Сохранение

Процедурные параметры связного — позиция, модель, shader и исходные нетронутые
предложения — восстанавливаются из `world.seed` и `poiIndex`. Сохраняются только
изменения мира.

Обязательные данные:

```ts
interface WorldState {
  courierStorage: Record<string, (Item | null)[]>;
  completedContractIds: string[];
}
```

`courierStorage` создаётся при первом изменении багажника конкретного связного и
после этого содержит полный снимок восьми ячеек. Нетронутый связной не
раздувает save.

Объекты, которыми владеет вид, сохраняются как обычные прицепы и машины
(`WorldState.trailers` / `.cars`), поэтому отдельного поля для них нет: id выводится
из seed предложения, а `TrailerState.load` несёт негабаритный груз. Удаление
(`trailer_remove`, `car_remove`) убирает объект из состояния и из сцены; после
перезагрузки он не появляется, потому что предмета, который его породил, больше нет.

Предмет содержит вид задания, индекс связного-источника, обычную награду, seed
генерации и `progress`. Его местонахождение сохраняется через `carried`,
`CarState.storage`, `WorldState.looseItems` или `courierStorage`; отдельного
указателя активного задания нет, и прогресс сохраняется вместе с предметом там, где
он лежит. Загрузчик (`sanitizeContractProgress` в `save/save.ts`) собирает
`progress` заново из известных полей и зажимает числа, поэтому старый или
испорченный файл грузится как свежий, не запущенный контракт.

Не сохраняются открытый UI багажника, prompt, видимость chunk, placement preview и
другие производные данные.

## Атомарность и инварианты

- один ID предмета существует ровно в одном хранилище;
- багажник обычной машины содержит не больше одного `contract_cargo`;
- багажник связного принимает груз только от меньшего `sourceCourierIndex`;
- сдача одновременно удаляет груз, создаёт конверт и записывает completed ID;
- побочный эффект вида (прицеп, машина, деталь) применяется ПОСЛЕ этого применения
  и потому не может заплатить дважды;
- загрузчик валидирует item union и длину каждого хранилища;
- найденный completed ID не может снова породить награду.

## Реализованный вертикальный срез

Работает полный путь:

1. связные появляются на POI через 6–12 км и узнаются по shader;
2. в каждом багажнике четыре предложения, вид каждого взят детерминированно из seed;
3. обычная машина принимает не больше одной посылки;
4. предмет можно держать, бросать, хранить и перекладывать;
5. более поздний связной превращает груз в подписанный конверт;
6. конверт можно забрать, переносить и сохранить;
7. конверт открывает preview наклейки на панели обычной машины;
8. подтверждение расходует конверт и навсегда сохраняет наклейку;
9. сериализация courier storage, completed ID, конверта, наклейки и `progress`
   проходит round-trip;
10. у каждого реализованного вида — своё условие и своя подписная наклейка;
11. виды 6, 7, 18, 19 спавнят свой объект у связного-источника при взятии груза,
    проверяют его пробой мира при сдаче и расходуют его в той же транзакции;
12. виды 11, 12, 13 работают: 11 форсит лысый компаунд на перевозящей машине,
    12/13 строят ворота из seed и дороги, считают прохождение по порядку и хранят
    счётчик и таймер в `progress` (проверяется round-trip сейва);
13. вид 20 снимает доказательство кадра на фотографию и принимает поручение только
    с подходящим снимком, расходуя его вместе с запиской.

## Буксировка (17) и конвой (16)

Обе подсистемы двигают ВТОРУЮ машину, и обе — про физику, а не про таймер.

**Буксировка.** Жёсткая сцепка между двумя кузовами: сферический шарнир Rapier с
совпадающими якорями (`src/vehicle/cartow.ts`), тот же тип связи, что у прицепа,
плюс прямая пост-шаговая коррекция растяжения. Выбран ШТАНГА, а не трос: у троса
есть фаза слабины (сближение, касание кузовов) и фаза рывка, а штанга держит
дистанцию и на сжатие, и на растяжение. Буксируемая машина заспавнена без
двигателя (`contracts/world.ts`), едет на нейтрали, без газа, её тормоза повторяют
педаль тягача, а передние колёса доворачиваются пассивно. Коррекция
скоросте-ограничена — штанга не может протащить машину сквозь мир, поэтому
застрявшая машина ОСТАНАВЛИВАЕТ сцепку (замер: 2.6 км/ч, 0.04 м хода), а устойчивая
нагрузка >20 мм в течение 1.5 с рвёт штангу. Демпфер рыскания гасит «змейку» —
измеренная критическая скорость пары без него 54 км/ч, с ним >70. Состояние —
`CarState.towedBy`, связь восстанавливается после загрузки в `reconcileActiveWorld`.

**Конвой.** Машина сопровождения — обычный сохраняемый `CarState` с собственным
`Autopilot` (реестр в `main.ts`, единственная запись). Режим следования — не новый
код в планировщике: корпус игрока виден планировщику как динамическое препятствие,
и штатное удержание дистанции само держит хедвей. Реестр задаёт только потолок
скорости (догонять / держаться / стоять, когда бумаги не в машине игрока) и
материализацию по радиусу стриминга: за радиусом выгрузки машина паркуется в
состоянии и продолжает с того же места, без телепорта. Сдача расходует машину.

## Осталось реализовать

1. Живой playthrough буксировки и конвоя: сцепка, сдача с неё, расход машины,
   save/load в пути. Числовые стенды — `tools/tow-convoy-bench.ts`.
2. После playtest настроить парковочные clearance, заметность shader и частоту
   связных, не нарушая гарантированный максимальный разрыв.
3. Настроить темп машины сопровождения: в стенде она держит дистанцию и тормозит
   вместе с игроком, но после длинной стоянки догоняет медленно и уходит на обочину.

Пройдено живьём (2026-10-05): ночной пакет взят у связного 0, сохранение и
перезагрузка в пути, сдача связному 1 ночью → конверт «луна», перезагрузка, конверт
взят и наклеен, перезагрузка — наклейка на месте. Touch-полоса примерки работает.
