# carforge

Builds a low-poly car FBX from a compact spec. Pipeline entry points:

- `carforge.py` — spec → FBX (`-- <spec.json> <out.fbx> [--wheel-fbx] [--summary <file>]`).
- `render.py` — FBX → PNG views (`-- --fbx <file> --albedo <png> --prefix <path> --size W H [--bg R G B] [--hide <name part>...]`; writes `_side`, `_front`, `_rear`, `_top` (orthographic, each with a `.json`: mm per px, centre, image axes), `_q`, `_qrear`, `_wire`; prints `EXTENT x y z`). Back faces are culled, as the game draws them, so a face turned inward shows as a hole. Render at `--size 3000 1760` when the views are for cropping details.
- `holes.py` — watertightness check (plain Python + Pillow/SciPy, runs `render.py`; `<car.fbx> [--prefix <path>] [--max <px>]`): the body without its wheels on magenta, and per view the background pixels inside the silhouette (`HOLES {...}`; `<prefix>_<view>_holes.png` marks them yellow; exit 1 above `--max`). Wheels are hidden because the arches are open to the road.
- `solid.py` — a reference's panels closed into one solid (plain Python + SciPy; run by `reduce.py`'s `skin`): surface voxels, a closing of `--close` mm fills slits, and the outside flood stops between the two sides and between nose and tail, so an open underbody or cabin is shut.
- `coplanar.py` — faces lying on top of each other, the cause of z-fighting (Blender script; `-- --fbx <file> [--box x0,y0,z0 x1,y1,z1] [--only <name>] [--gap <mm>]`): pairs closer than the gap that overlap, `same` (both show: a fight) or `opposite` (back to back: harmless).
- `trace.py` — line drawing → pixel blueprint, no hand tracing (plain Python + OpenCV; `<sheet.json> <blueprint.json>`; also writes `<blueprint>.trace_report.json`, the details taken and the candidates dropped; see "Automatic trace").
- `lines.py` — filled, watermarked colour blueprint (a the-blueprints.com preview) → line drawing for `trace.py` (plain Python + OpenCV; `<drawing> <out.png>`): the watermark inpainted, every colour boundary an edge, each view's outer border drawn so its silhouette is closed; 2 px lines.
- `reduce.py` — a detailed reference model (glTF) → a pack-style car FBX (Blender script; `-- <reduce.json> <out.fbx>`): the shipped VAZ-1111; see "Reducing a reference model".
- `fit_blueprint.py` — traced pixel blueprint → spec (plain Python).
- `fit_mesh.py` — existing FBX/GLB → spec (Blender script; `-- --in <fbx> --out <json> --id <id>`).
- `fairness.py` — surface check of a built body (Blender script; `-- --fbx <file> [--prefix <path>] [--json <file>]`): counts folds (non-planar quads), ripples (a gentle bend reversed within 700 mm along a section profile) and slivers; writes a defect map (`_fair_*`) and a glossy matcap render (`_shine_*`). A body is clean at 0 folds, 0 ripples.
- `compare.py` — a render over the traced drawing at the blueprint's scale, in one view (plain Python + Pillow; `--blueprint <json> --drawing <img> --render <render.py prefix> --out <png> [--view side|front|top|rear]`, default side).
- `refgrid.py` — a glTF reference car normalised to the spec frame by its wheel objects and the factory wheelbase, and measured with rays (Blender script; `-- --in <glb> --wheelbase <mm> [--fbx <out>] [--grid <json>]`): the normalised FBX for `render.py`, and a grid of half-widths per (y, z), heights per (y, x) from above and below, and end-face y per (x, z), glass on its own. The numbers the VAZ-1111's spec was read from.
- `examples/` — hand-written specs (`uaz3151.json`, `vaz2101.json`, `bmw_e46.json`), the UAZ
  blueprint input, `sheet_gaz31029.json` (GAZ trace input), `gaz31029.json` (the reviewed
  generated shell spec), `reduce_vaz1111.json` (the shipped VAZ-1111), and `sheet_vaz1111.json`
  with `vaz1111.json` (the Oka's carforge spec, built and reviewed but not shipped).

Run Blender jobs one at a time, under `nice -n 15`:
`nice -n 15 /Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python SCRIPT -- args`

## GAZ-31029 workflow: trace, refine, generate

The shipped GAZ-31029 is generated by `carforge.py`. The AKROM model is a reference for checking
the shape, not a source mesh for the shipped body or trim:

1. `lines.py` turns the filled, watermarked preview into a line drawing while preserving the
   silhouette and closed wheel outlines.
2. `trace.py` reads `examples/sheet_gaz31029.json` and writes
   `build/carforge/gaz31029/blueprint.json` plus its trace report. The sheet supplies only the
   view boxes, wheelbase and the few details the drawing cannot prove.
3. `fit_blueprint.py` provides a generator-shaped starting point. `examples/gaz31029.json` is the
   reviewed final spec: the traced profile and plan are corrected against AKROM's hood, roof,
   glass, arches and tail, then faired with `fair_tol: 10`.
4. `carforge.py` builds the watertight body, floor, panel gaps, recessed glass, grille bars,
   bumpers, mirrors and lamp objects directly from that spec.

```
python3 tools/carforge/lines.py \
    build/vehicles/gaz31029/00-references/bp-31029-vector-full.jpg \
    build/vehicles/gaz31029/lines.png
python3 tools/carforge/trace.py \
    tools/carforge/examples/sheet_gaz31029.json \
    build/carforge/gaz31029/blueprint.json
nice -n 15 $BLENDER --background --factory-startup \
    --python tools/carforge/carforge.py -- \
    tools/carforge/examples/gaz31029.json build/carforge/gaz31029/shell.fbx
cp build/carforge/gaz31029/shell.fbx public/models/carforge/gaz31029.fbx
bun tools/fit-models.ts cf_gaz31029
```

The final spec deliberately keeps the AKROM comparison separate from generation. This avoids
the earlier hybrid failure: importing its open trim and collapsing it into one triangle budget
destroyed the grille and bumper. The generated model stays closed and owns its details; AKROM
only supplies the comparison views and measured shape corrections.

## VAZ-1111: generated, the GTA model as the reference only

The shipped Oka (`cf_vaz1111`) is built by `carforge.py` from `examples/vaz1111.json`, numbers
from `refgrid.py`'s ray grid over the GTA SA Oka the game used to ship (`sa_oka`, retired;
`git show 8f5a795:public/models/saas/oka.glb`). The GTA model is the reference for renders and
measurements only; none of its geometry ships.

```
nice -n 15 $BLENDER --background --factory-startup --python tools/carforge/carforge.py -- \
    tools/carforge/examples/vaz1111.json build/carforge/vaz1111/car.fbx
nice -n 15 python3 tools/carforge/holes.py build/carforge/vaz1111/car.fbx
cp build/carforge/vaz1111/car.fbx public/models/carforge/vaz1111.fbx
bun tools/fit-models.ts cf_vaz1111
bun tools/reality.ts cf_vaz1111
```

Still off against the reference: the front (a black panel across the lamps where the real car
has a painted panel round them and a narrow barred grille between; a thick bumper where it has
a thin band with a plate recess) and the bonnet's front corners. They are fixed in the
generator, one at a time, each checked against the reference (silhouette rows, close crops,
`holes.py`).

The GTA model reduced by `reduce.py` (`examples/reduce_vaz1111.json`) was shipped for a while
and taken out: closer in shape, but a reduced game mesh keeps its stray triangles (dirty
creases, a chewed rear bumper, glass unlike the pack's) and the slits between its panels.
Rules the generated Oka added for carforge specs:

- **The nose must carry its lamps.** The front face is the first station's ring, its top
  corners cut by the rail chamfer and its top edge crowned 25 mm: the nose top goes up to the
  bonnet lip and `rail` drops to 15 mm there, so the face is flat behind the lamps.
- **A mirror stays above 55% of the body's height**: the loader measures the published width
  below that, and a mirror under it widens the measured shell and squeezes the car.
- **The wing top is one edge** (owner's review, twice). Under the bonnet `shoulder` stands
  above the rail and `plan.high` equals `plan.low`, so the side runs straight up into one
  rail chamfer of constant width. A shoulder under the rail left a vertical strip between two
  bevels, `high` inside `low` a step, a rail changing along the bonnet twisted facets.
- **An A pillar is a strip of constant width, not a triangle** (owner's review): the door
  glass's front edge parallel to the windscreen line ~110 mm under it, the screen's `rail`
  15 mm, back to 30 only past the roof's front roll.
- **The windscreen starts at the cowl's knee**: the bonnet's rear stays under the side glass's
  bottom up to the knee, or the screen's glass (rule 5) runs onto the bonnet.

A projection of the station grid onto the reference (rings and end grids moved onto a solid
built from five ray height fields) was tried twice and dropped: the fields disagree at the
ends, so the end grids fell into the lamp and number-plate pockets, and rows at the spec's
heights cut across the reference's folds.

## How the GAZ-31029 was made: what to repeat, what to avoid

The GAZ-31029 is the first carforge car the owner called finished and in the style of the
pack (2026-10-12). It took two sessions and three rounds of owner review. This section is the
route that worked, in order, and every mistake that cost a round, so the next car costs one.

### The route

1. **References, before any geometry.** One four-view drawing (the-blueprints.com watermarked
   preview: side, front, rear, top at one scale), five to eight photographs (Wikimedia Commons:
   front, rear, both three-quarters, side, a night shot, a museum shot; crop them, they are
   the only source for lamps, trim and how panels meet), and a 3D reference if one exists
   (AKROM's GTA V model). Keep them under `build/vehicles/<car>/00-references/`; nothing
   from them is shipped. Look up what neither shows (the fuel flap's side came from parts
   catalogues: "заднее левое крыло 31029, отличие от 3102 в расположении лючка").
2. **Trace, then hand-refine one spec.** `lines.py` → `trace.py` → `fit_blueprint.py` give
   the silhouette, plan, wheels and arches; `examples/<car>.json` is then edited by hand and is
   the only input of the build.
3. **Measure the drawing, do not eyeball it.** Crop each region of the drawing, enlarge it 4-8×
   with a grid line every 5 or 10 drawing pixels, and read pixel positions; the blueprint's
   `scale` turns them into spec millimetres (`y = (px − y0_px)·mm_per_px`,
   `z = (z0_px − py)·mm_per_px`; the GAZ sheet: 5.767 mm/px, y0 161, z0 331.7). Lamps, grille,
   bumper heights, handles, the vent, the flap and the mirror were all placed this way.
4. **Normalise the 3D reference and compare numbers.** Scale it so its wheelbase is the
   factory one (AKROM: 2.987 units, ×0.9374), unpitch it about the front hub (−1.08°), put the
   ground at z = 0 and the front hub at y = 0, and render it with `render.py`. Then compare
   the two side silhouettes row by row (first and last body pixel every 50 mm of height).
   This found the one error the eye had accepted for a whole session: the nose 180 mm short.
5. **Overlay on the drawing.** `compare.py --view side|front|top` after every build; zoom the
   nose and the tail of the overlay. Arch shapes, the tail's lean and the sill behind the rear
   arch were all corrected from these crops.
6. **Look at it as the owner will.** `render.py` at 3000×1760, crop to the car, then zoom the
   front three-quarter, rear three-quarter, front and side. Then the game: your own Vite on
   another port (`npx vite --port 5199 --strictPort`), one tab at
   `/?car-lab&focus=<id>&time=12`, `window.__carLab.focus(<id>, <azimuth>)` and the mouse wheel
   to get close. Close the tab and stop the server after.
7. **Ship.** Copy the FBX to `public/models/carforge/`, `bun tools/fit-models.ts <id>`,
   `bun tools/reality.ts <id>`, `bun tools/handling-cli.ts <id> <sibling>` (the sibling: the car
   it shares a chassis with, here `sv_gaz24`), then the realism checklist below.

### What worked

- **The generator owns every face.** No mesh from a reference is shipped; an earlier hybrid
  that imported AKROM's trim destroyed the grille and bumper in the triangle budget.
- **Few, flat, chunky details read as the pack.** A rectangular lens 8-9 mm proud, a dark
  housing behind lamps, a black wrap bumper with one moulding groove, vertical grille bars in
  a chrome frame. Detail the pack does not have (badges, the deer, fog lamps, wipers) was
  left out on purpose.
- **An owner correction that applies to every car becomes a generator rule, not a spec
  tweak.** The windscreen and back light now end where the side glass does (rule 5); lamps
  and bumpers can wrap a corner (`wrap`); a lamp may sit in a `housing`.
- **Panel gaps as the only way to show parts.** The boot lid, bonnet front, fuel flap and doors
  are all `grooves`; a closed groove is a flap.

### What cost a round, and the rule that prevents it

| Mistake | Why it happened | Rule |
|---|---|---|
| Nose 180 mm short, bumper hanging in the air | AKROM was compared by eye at its own scale | Normalise the reference (step 4) and compare numbers before any detail work |
| Windscreen and back light not level with the side glass | A fixed 60 mm paint frame | Glass heights come from the side windows (rule 5) |
| Rear lamps as four tiles with gaps per side | Laid out from the drawing's colour blocks | Zoom every lamp in the photos: count the units, see where panel gaps run through them, sections of one unit touch |
| Front and rear indicators as a front piece plus a side piece | `lamps` only knew one face | `lamps[].wrap`: one lens round the corner |
| Indicators upright seen from the side, the real ones lean | Not checked in a straight side photo | Check every lamp's edge in a true side view; `wrap: [bottom, top]` slants it. Fan the lens from one point and move only its side edge: a fan per row breaks it into steps |
| Front arch wider and lower than drawn | A hand semicircle | Use the traced outline in mm |
| The tail's top rolled over concave (a dent) | Top and shoulder points fell too steeply into a large `tail.bulge` | Keep the last points convex (each drop larger than the one before); check the rear three-quarter for dents |
| The boot lid's gap broken at the corner | The top groove ran onto the roll-over and the rear one started lower | Gaps on two faces meet at one shared point; the top one stops before the roll |
| A step in the sill behind the rear arch | `side.bottom` jumped 245 → 350 mm after the arch's end | The bottom line crosses the arch's end at the arch's own height, then climbs |
| Grille lower than the photo | Placed level with the lamps | Read the margins from a straight-on photo (equal above and below the lamps here); the bonnet's edge rises over it |
| Mirror a floating box | One box | A head on a base that reaches the window corner |
| Z-fighting inside the grille | The frame's inner wall lay on the pocket's wall | Nothing new may share a plane with an existing face: run `coplanar.py` over each new detail |
| The UAZ's spare moved to cure its z-fight | The spare is in the measured body box, so its move changed the fit | A cosmetic part never moves the body; add a mount (`chassis` boxes) instead |
| The drawing's white panels taken for detail | They are number-plate frames | No number plates or their frames |

### Realism checklist (what is checked before a car ships)

`reality.ts` holds the first five to the factory; the rest are read from the bench and the
catalogue entry against a sibling car and the sources in the entry's comment.

- Proportions: length, width, height, wheelbase, both tracks, overhangs (render and overlay).
- Wheels: rolling radius from the factory tyre (205/70R14 → 0.321 m), tyre width, radial or
  cross-ply.
- Engine (power, torque and their speeds) and gearbox (ratios, final drive): top speed against
  the passport, 0-100 where a factory figure exists.
- Turning circle; braking from 80 km/h laden under the factory ceiling.
- Kerb and gross mass, front weight share, tank.
- Suspension (the sibling's tuning when the chassis is shared), ride height and clearance,
  skidpad g, roll, ride frequency (printed, not held).
- Drag (Cd·A from the top speed, or the sibling's when the cut in top gear comes first).
- Lights: every lamp role named in the catalogue entry exists as a node.
- Who drives it (`DRIVER_ODDS` in `src/world/traffic.ts`).

## Reducing a reference model (`reduce.py`)

The VAZ-1111's route (above). The config's keys beyond the module docstring:

- `parts.<mesh>.panel`, `trim.panel`, `lamps[].panel` (degrees): after the collapse to `tris`,
  neighbouring faces within that angle are dissolved into one panel and triangulated across
  it (BEAUTY), so a panel shades as one flat face instead of a crumple of small triangles. A
  panel whose triangles or corners stand off the collapsed surface by more than
  `PANEL_OFF_SURFACE` (a seal bending round a window, the bonnet's lip) gets its faces back:
  across itself it showed as dark shapes over the glass. Flattening the panels onto planes as
  well tore the tailgate open and is not done.
- `trim.drop`, `parts.<mesh>.drop`: `{min_mm, boxes}`: loose pieces smaller than `min_mm`, or
  centred in a box (`[x0,y0,z0,x1,y1,z1]` mm, or `{box, max_mm}` for only pieces up to that
  size) are dropped: wipers, number plates, badges, the tow hook, the headliner and the cabin
  seen through the glass. A box must not reach a panel of the body: the GTA tailgate is one
  piece with its wiper's base, and dropping that cut a hole in it.
- `flat`: every face flat shaded, as the pack's are (no edge split).
- Every piece is turned to face away from the car's centre line; a face that ends up glass is
  judged on its own, turned out if it faces in (the GTA back light is a trim plate drawn inside
  out) and dropped if it stands across (a pane's edge, a dark triangle over the glass).
- `cells` boxes paint the engine bay seen through the grille and the number-plate opening
  black, and the back light's plate glass.
- `skin: {voxel_mm, close_mm, inset_mm, tris}`: a reference built of panels has slits between
  them and the sky shows through the car. The kept surface is closed into a solid
  (`solid.py`, `voxel_mm` 10, `close_mm` 20), its voxel boundary Taubin-smoothed, reduced to
  `tris` and laid `inset_mm` under the reference face each vertex looks at (at most 0.4 of the
  solid's thickness there, so a bumper's wing is not crossed). Each face takes the colour of
  the reference face nearest it (majority over its neighbours), carried through the collapse
  as a UV, so a slit shows the panel's own paint. Check with `holes.py`. Making this skin the
  body itself, reduced to panels, lost the window frames' crisp edges to the voxels and
  dented where it was laid back on the reference; it stays under the panels.

`reduce_gaz31029.json` is a comparison experiment only, not the shipped Volga. Its reference is
AKROM's GTA V model, kept locally as `build/vehicles/gaz31029/00-references/akrom-gaz31029.glb`.

## Frame and units

- All spec values are millimetres.
- y runs rearward from the front-axle centre (front of car is negative y).
- z runs up from the ground plane (wheels rest at z = 0).
- x runs to the car's left (positive x = left, mirrored features are symmetric about x = 0).

## Spec schema

| Key | Type | Units / frame | Meaning |
|---|---|---|---|
| `id` | string | — | Object name prefix (`<id>.body`, `<id>.body.<role>`, `wheel_fl` etc.). |
| `wheels.radius` | number | mm, tyre outer radius | Wheel radius. |
| `wheels.width` | number | mm | Tyre width. |
| `wheels.track_front` / `track_rear` | number | mm, wheel-centre to wheel-centre | Track width per axle. |
| `wheels.wheelbase` | number | mm, front axle to rear axle | Axle spacing. |
| `wheels.arch_front` / `arch_rear` | number | mm | Wheel-arch cut radius. |
| `wheels.well` | number | mm, optional | Extra arch-well depth. |
| `side.top` | [[y,z], …] | mm, ≥ 2 points | Roof/silhouette top profile. |
| `side.bottom` | [[y,z], …] | mm, ≥ 2 points | Sill/underbody bottom profile. |
| `side.shoulder` | [[y,z], …] | mm, ≥ 2 points | Shoulder line where plan width changes. |
| `plan.low` | [[y,half_width], …] | mm, ≥ 2 points | Body half-width below the shoulder. |
| `plan.high` | [[y,half_width], …] | mm, ≥ 2 points | Body half-width above the shoulder (greenhouse). |
| `tumblehome` | [[z,factor], …] | mm / unitless | Inward taper of the upper body; factor 1.0 = no taper. |
| `belt` | number | mm, z of beltline | Belt height. Required. |
| `glass_top` | number | mm, z of top of side glass | Required. |
| `windscreen` | [y0, y1] | mm | The windscreen slope's span along y. The glass on it is found by rule 5. |
| `backlight` | [y0, y1] | mm | The back light slope's span along y (rule 5). |
| `windows` | [{y:[a,b], outline?, round?}, …] | mm | Side windows, each a pocket cut 12 mm into the greenhouse side (glass floor, dark seal walls). `outline`: traced [[y,z], …] corners (slanted pillars); without it the window runs belt→glass top and drops under the rail. `round`: corner radius (default 40). |
| `seams` | [[[y,z], …], …] | mm | Side panel gaps: same as `grooves` with face `side`. |
| `grooves` | [{face, line, closed?, width?, depth?, single?}] | face coords (below) | Panel gaps: a V 10 mm wide, 8 mm deep folded into the paint, as the pack does its door gaps (one swept wedge per line, square to the surface). Side gaps stay on the side surface: above the sill chamfer and below the rail (`Shape.rail_z`), never over the roof, bonnet or pillar chamfer. The UAZ's bonnet, full width and wrapping down the sides as on the drawing, is three gaps: along each side, across the front face and across the top at the cowl. |
| `rail` | [[y, mm], …] | mm, default 55 everywhere | The chamfer between the side and the roof, bonnet or pillar top, per y. The UAZ's A pillar has almost none (8 mm): the 55 mm one was a third plane between the side and the screen frame, and left the front door's frame no side to be cut in. |
| `lines` | [{face, line, closed?, width?, cell?, single?}] | face coords | Drawn ribbons 3 mm proud, for what is painted rather than cut: bonnet ribs, fuel flaps. |
| `recesses` | [{face, x\|y, z, radius?, round?, depth?, cell, bars?, frame?, housing?, single?}] | face coords | Pockets with a flat floor in `cell`: windscreen and back-light glass, grille openings, lamp housings. `radius` rounds the corners (half the height = stadium). `bars: {count, width, cell, orientation?, inset?, x?}`: grille bars standing in the pocket, over `x` only when given; a list of them (horizontal and vertical) is a grid. `frame: {width, proud, cell}`: a flat surround round the opening (the GAZ-31029 grille's chrome). `housing`: a lamp cluster's dark body; lamps may sit in it (rule 3). |
| `arches` | {front\|rear: {outline, lip?, flare?}} | mm | Arch opening edge in side view (default: semicircle of `arch_front`/`arch_rear`), with a lip `lip` mm wide standing `flare` mm proud. |
| `nose` / `tail` | {bulge, inset} | mm | Bulged end: the last station stands `bulge` inside the end, a band rolls in by `inset` to the end face. |
| `fair_tol` | number | mm, default 12 | Trace noise below this is dropped from the side/plan curves (Douglas-Peucker). A sheet's `extras.fair_tol` reaches the spec. |
| `redraw` | {top\|bottom\|shoulder: [[[y, z\|null], …], …]} | mm | Each polyline replaces the side line over its own span, the traced points there dropped; a null z keeps the traced height (two nulls: a straight chord). Its points are kept as given (`fair_tol` fairs only the traced stretches between them), so a hand-drawn curve keeps its segments. For what the drawing shows and the car does not: the UAZ sheet's bonnet rising 80 mm with a step across it (the factory bonnet is flat, rolling over at the front on a ~150 mm radius), its sill's bumps by the arches. |
| `bumpers` | [{y, z, half_width, cell, chamfer, channel?, lip?, ends?, wrap?}] | y, z: [lo,hi] mm; half_width mm; cell: atlas material name; chamfer mm | Bumper boxes at the nose/tail. `channel`: the outer face is a channel that deep between `lip`-tall lips. `wrap: {to, radius, segments?, groove?: {z, width, depth}, profile?}`: one section (`y`'s depth thick, `z` tall, edges chamfered) swept across the end, round both corners on `radius` and back along the sides to y = `to`, its outer face at ±`half_width`; `groove` is a V moulding line along it (the GAZ-31029's plastic bumpers). `profile` [[in, z], …] bottom to top, mm back from the outer face, replaces the chamfered face with a measured section (the VAZ-1111's: the foot tucked in 40, the face bulging, the top a shelf back to the body). |
| `cells` | [{y, z, x?, cell}] | mm boxes, \|x\| | Shell quads whose centre falls in a box take its cell instead of paint: the VAZ-1111's front panel between the bumper and the bonnet is black plastic in the body's own skin. |
| `mirrors` | [{x, y, z, cell, chamfer?, single?}] | mm boxes, mirrored to the right unless `single` | Wing mirror heads and their bases (the GAZ-31029: a head over the door top by the A pillar, a short base into the window corner; the VAZ-1111: one, `single`, on the driver's door). |
| `chassis` | [{x, y, z, cell?, chamfer?, single?}] | mm boxes, mirrored to the right unless `single` | Running gear seen under the body: frame rails, axle beams, differential housings. The lowest one sets the body's ground clearance in the game (the loader fits the body box between `clearance` and `height`), so a body without an underbody of its own needs them. |
| `plates` | [{face, x\|y, z, cell, round, radius, proud?, single}] | face coords | Blocks standing on a face: number plate, door handles, hinges. Probed onto the body with its bumpers, so a plate on a bumper (the VAZ-1111's rear fog lamp, cell `lamp_tail`) stands on the bumper. |
| `lamps` | [{role, face, x\|y, z, round, segments, single, bezel?, dome?, rim?, proud?, wrap?}] | face coords; face `front`/`rear`/`side` | Lamp boxes. `role` must be a key of `LAMP_CELL` in carforge.py (`headlights`, `leftblinkers`, `rightblinkers`, `taillights`, `reverselights`); a side blinker becomes left/right by its side. A lamp's lens is flat, `proud` (8) mm off the outermost point of the face under it, so a crease under a lamp never shows through it. `dome`: a chrome rim (`rim` mm proud) round a lens bulging `dome` mm, like the pack's headlamps; the rim is built into the body, the lens alone is the lamp object, because the game lights a lamp object whole. `bezel`: the lamp sits in a pocket that much wider. `wrap` (front/rear lamps): the y the lens reaches back to along the side; it turns the corner as one piece (rays fanned in plan from the inner edge `x` and `wrap`, `proud` along each), so `x` gives only the inner edge. `wrap: [y bottom, y top]` slants that edge seen from the side (the GAZ-31029's front indicators lean back towards the bonnet, the rear ones forward towards the boot: front −745/−700, rear 3780/3825). |
| `spare` | {y, z} | mm | Spare-wheel hub (optional): its own object `<id>.spare` (the pack wheel), which the game replaces with a wheel of the car's own set (`spareNode` in `src/vehicle/carmodels.ts`). |

Face coordinates (mm): `front`/`rear` (x, z); `side` (y, z) on the left side, mirrored to the right; `top` (y, x). Items are mirrored across the car unless `single`; a `single` side item stands on the left, or on the right with `right: true` (the VAZ-1111's fuel filler); every item is probed onto the body along its face's axis.

`validate()` in carforge.py rejects specs missing `id`, `wheels` (radius, width, track_front, track_rear, wheelbase), `side.top/bottom/shoulder` (≥ 2 points), `plan.low/high` (≥ 2 points), `belt`, `glass_top`, unknown lamp roles, and lamp faces other than `front`/`rear`/`side`.

## Rules the generator enforces

Taken from the owner's reviews, so the next car does not need the same corrections by hand:

1. **Glass follows its pillar.** `windows[].pillar: "a"|"c"` turns the window's front (rear) edge parallel to the body's A (C) pillar from the traced silhouette, pivoting on its bottom corner.
2. **A door edge follows the glass it frames.** A line point `{edge: [window, "front"|"rear"], offset, z}` expands to a segment parallel to that window edge, `offset` mm along y (the frame's width).
3. **Details do not sit on each other** (`check_layout`, run before the build): lamps, plates, recesses (with their `frame`) and side windows keep 8 mm plus the gap's half width from every panel gap and do not overlap each other; a closed gap (a fuel flap) keeps clear of every other gap; being inside a door outline is fine; a `straddle` plate (a hinge) may cross gaps; lamps sit in a `housing` recess. The build fails with every clash listed.
4. **Panel gaps never cut the body's edge:** side gaps stop above the sill chamfer; arch lips end above it with their flare run out.
5. **The windscreen and back light end where the side glass does** (`screen_glass`): on the slope through `windscreen` (`backlight`) the glass is the run where the roof edge row (top − CROWN) stands between the side windows' lowest and highest glass, so the screens' bottom and top edges line up with the side glass's (owner's review of the GAZ-31029: the fixed 60 mm frame left them higher and lower). The run may leave the span where the slope rolls into the roof.

## Blueprint input (`fit_blueprint.py`)

Input is a traced side (and optionally front) blueprint in pixels. Keys:

- `id`, `source` (text note).
- `scale`: `mm_per_px`, `y0_px` (px column of front axle), `z0_px` (px row of ground), `x0_px` (px column of car centre-line for front view). Optional view anchors used only by `compare.py`: `top_x0_px` (top view centre row; the top view's columns are the side view's), `rear_x0_px` (rear view centre column), `deskew` `{deg, centre}` (the rotation `trace.py` applied to the scan; `compare.py` rotates the drawing the same way).
- `side.top`, `side.bottom`, `side.shoulder`: `[[px,py], …]`.
- `plan.low`, `plan.high`: `[[px, half_width_px], …]`.
- `tumblehome`: `[[py, factor], …]`.
- `belt`, `glass_top`: py.
- `windscreen`, `backlight`: `[px0, px1]`; `windows`: `[[px0, px1], …]` or `{outline, round?, pillar?}` (flags copied).
- `lamps`: front lamps in px (`circle [cx,cy,r]` or `rect [x0,y0,x1,y1]`), rear lamps in mm (`x`, `z`).
- `wheels`, `bumpers`, `mirrors`, `plates`, `spare`: already in mm, copied through.

Mapping: y = (px − y0)·mm_per_px; z = (z0 − py)·mm_per_px; x = (px − x0)·mm_per_px.
`examples/blueprint_uaz3151.json` round-trips exactly to `examples/uaz3151.json`.

What is measured, in order (the module docstring and each function's docstring hold the exact rules):

1. **Wheels and scale.** `cv2.HoughCircles` (gradient-alt) in the side box; every candidate is refitted by least squares on the ink's distance map, and the outermost ring inked round ≥ 85 % of its length about that centre is the tyre. A drawing that shades the wheel well as dark as the tyre loses the tyre's top in the arch: a ring inked ≥ 85 % over its half under the hub (fitted on that half, looked for out to 2 radii) then wins when it is over 15 % larger than the whole-ring one, which was the rim. Hough candidates at one centre are kept apart when their radii differ by 15 % (rim and tyre). The pair of equal tyres on one row with the largest radius are the wheels: scale = wheelbase / hub distance, ground row = hub row + tyre radius, tyre radius → `wheels.radius`.
2. **Deskew.** If the two hubs are not on one row the scan is rotated about the front hub until they are, and the wheels are refitted (`scale.deskew`). The UAZ scan is turned 0.47° (the top view's centre line and axis lines confirm it).
3. **Silhouettes.** Per view, the pixels not reachable from the box border through non-ink (ink grown by a pixel to close gaps, the mask shrunk back), cut at the hub row + 0.75 tyre radius so the ground line and hatching never close a loop, then opened by 3 px to drop thin lines (extension lines, axis lines).
4. **Body ends.** The columns where the side silhouette stands ≥ 50 % of the car's height (drops a low bumper) and the top view is ≥ 60 % of its widest (drops a spare wheel carried behind), trimmed to stop where an extras bumper box begins.
5. **`side.top`**: the silhouette's first row per column, spikes narrower than 60 mm opened away.
6. **`side.bottom`**: down each column outside the wheel discs, the lowest clear (ink-free) run ≥ 70 mm tall is body side and the ink band under it is the sill; its lower edge is the underside. Chassis parts (frame rails, springs, exhaust) are lines with short gaps, so they are skipped. A 21-column median per stretch (front overhang, between the wheels, rear overhang); nothing hangs more than 1 px below the median sill between the wheels; within 200 mm of an extras bumper box an underside still below the box's top is put at the box's top (the bumper hides the body there).
7. **Plan (top view)**: centre row = median mid-point of the silhouette columns (`top_x0_px`). `plan.low` = half-width of the filled run through the centre row, both sides averaged, with a 250 mm grey opening that removes the mirrors. `plan.high` = the outermost line drawn symmetrically about the centre row, 6 px or more inside `low` and outside 60 % of it (bonnet edge, roof gutter), opened the same way, notches under 120 mm along the car closed (a pillar line crossing the glass edge), capped at the front view's half-width at the belt (the gutter stands out past the glass). Under each arch the top view's outline is the arch lip's edge, and carforge stands the lip `flare` mm proud of `plan.low`; so `plan.low` there is the outline less the lip's flare profile (`lip_flare()`: full flare over the opening, run out over 80 mm of the outline at its ends and across the `lip` band, as carforge builds it), but no further in than the body line bridged across the arch (see "Known limits"). `TRACE` prints the cut (`arch_lip_cut_mm`) and how far the drawn outline stands past the body line bridged across the arch (`arch_drawn_proud_mm`).
8. **Front view**: the track and the centre column from the tyres (under the axle, clusters of vertical lines spanning 0.3-1.2 tyre radii; lone extension and centre lines are not tyres). Half-width per row of the run through the centre column, mirror arms and brackets removed by an 80 mm grey opening; over the rows of the sheet's `mirrors` (±20 mm) it is capped at the body's width just under them. `tumblehome` = half-width / half-width at the greenhouse's base. On a saloon the wings and cowl stand past the glass just above the side windows' bottom edge: the base is the foot of that step (the first row within 150 mm over the belt 5 % narrower than the belt, followed while it narrows by 2 % per 2 px), the profile runs from it to the glass top and on above it while each 2 px narrows it by no more than 3× the glass's mean (the pillars keep their lean up to where the roof rounds over), and `plan.high` is capped at the base's width (GAZ-31029: 805 mm at the base, 0.837 of it at the roof rail). Without the step (the UAZ) it runs from the belt until it falls under 0.9, and `plan.high` is capped at the belt's width. `shoulder` = the first row under the belt where the half-width is past half-way from the belt's to the body's widest.
9. **Windows**: background regions inside the side silhouette that are ≥ 120 mm thick, ≥ 12 % of the car's height tall, end above roof + 55 % of the height and have holes of at most a quarter of their area; regions under 50 mm apart (a divider, a seat or wiper line) merge. Each window's frame is the ink within 4 px of its glass; what that encloses is the window. Its four sides are supporting lines through the outermost pixels (a seat or box against the frame only pushes points inward), front and rear fitted on the rows 12-55 % down the glass, where no dash or seat is. A region whose fitted corners land more than a quarter of its size outside it is a triangle (the back light's edge seen past the C pillar) and is dropped. `round` = median corner radius from the gap between the sharp corner and the glass; the first window gets `pillar: "a"` when its front edge leans back, the last `pillar: "c"` when its rear edge leans forward. `belt`/`glass_top` = median window bottom/top.
10. **Windscreen and back light**: where the side top line crosses half-way between the belt and the roof, first from the front and from the rear, the stretch it climbs (falls) at least 30 % as steeply as there, the line smoothed over ~50 mm; taken as `windscreen` / `backlight` when it runs along the car at least 0.8 times as far as it rises. An upright screen (the UAZ's) is not taken: the sheet gives it as a front-face recess.
11. **Arches**: the non-ink gap between the tyre and the fender (the region hugging the tyre's upper half, outside the disc, above the underside line); the first ink above it per column is the arch edge. Where the gap pinches shut, the end segment's slope runs on to 3 px below the underside. `wheels.arch_front/rear` = the edge's height over the hub.
12. **Details** (below).

All polylines are Douglas-Peucker simplified at 1.2 px. `TRACE {...}` reports the measured scale, hubs, track, extents, belt/glass rows, window spans, the arch lip cut and the number of details; then two tables follow (`DETAILS taken`: view, kind, position in mm, evidence; `DETAILS dropped`: view, kind, position, reason), also written to `<blueprint>.trace_report.json` (`build/carforge/trace/blueprint.trace_report.json`).

### Details

The small body details are found on the drawing itself. A detail is taken only on strong evidence: a drawn line or closed outline of a plausible size for its kind, in the right region, with its partner where it has one. Everything that looked like a detail and failed a rule is dropped into the report with the rule it failed. Nothing inside the side windows (the window quads grown 2 px) is ever a candidate: seats, the steering wheel and the mirror stalk behind the glass are counted (`note: side: N closed shapes inside the window glass ignored`) and skipped; the front view looks only between the bumper's top and the belt (the windscreen with its wipers and steering wheel is above it); bonnet ribs only ahead of the first window.

Every rule is relative, so it is meant for any drawing, not the UAZ: sizes and distances are fractions of the wheelbase (`*_WB` constants in `trace.py`; the wheelbase is the one dimension every sheet gives) or multiples of the drawing's own line width (`*_LW`; `stroke_width()` = the median length of the ink runs across rows and columns, 2 px on the UAZ scan). Positions are taken against traced features: the belt, shoulder and sill rows, the window outlines, the wheel discs, the arch outlines, the front and top centre lines, the bumper's top. The sizes below are quoted in mm and px **at the UAZ's scale** (wheelbase 2380 mm, line width 2 px) for reading; the code holds the fractions.

Shapes: thin drawn lines are found as Hough seeds refitted to their ink (one sample per row, so a box edge touching the line does not tilt it), followed while ink continues (breaks ≤ 3 px: the scan dithers thin lines) and merged when collinear (ends within 2 px of the longer line's line); a steep line may bridge an 80 mm break (a hinge box interrupts it), a level one may not. Closed shapes are background regions enclosed by ink ("holes") and ink pieces touching nothing else ("blobs"), ink first closed by one pixel.

| Kind (blueprint key) | Taken when | Emitted |
|---|---|---|
| Door / panel gap (`seams`, px) | A chain of straight drawn lines inside the body side, outside the glass, whose lower end is within 25 mm of the sill line and whose upper end is at the belt or higher (no lower than 15 % of the belt-to-sill height under the belt): it crosses the side. A chain bends only where a line ENDS (within 50 mm of the bend) near the other's end (within 100 mm) and rises ≥ 100 mm above the bend: a corner, not a crossing. All of it ≥ 100 mm inside the body's ends. Of chains reaching as high, the one with fewer bends. | The drawn polyline (top to sill); carforge's default 18 mm V, stopped above the sill chamfer and under the rail. Evidence lists a parallel gap 2-12 px away (the two door edges either side of a pillar) and the hinges on it. |
| Hinge (`plates`, paint, `straddle`) | A hole 30-110 mm a side, ≤ 2:1, filling ≥ 75 % of its bounds (a box), ≥ 60 % of its rim its own (not on a long line other than the gap), a taken gap passing through it, between the belt and the sill, and a second such box on the same gap (a door hangs on two). | The box (outline centre) in mm, `proud` 12. |
| Handle (`plates`, steel) | A blob 100-300 x 20-80 mm, ≥ 2.5:1, enclosing something (a closed outline), centred between the belt and half-way past the shoulder, between two taken gaps (inside a door). When there are several candidates, each needs one on another door on the same row (one line width) and of the same length (15 %); a lone candidate stands on its own evidence. | Its ink bounds, `proud` 20, `radius` 15. |
| Flap (`grooves`, closed; a fuel or service flap) | A hole 100-350 mm a side, filling ≥ 75 % of its bounds, rounded (corner radius ≥ 10 % of its short side), ≥ 70 % of its rim its own (a panel bounded by gaps and creases is not a flap), inside the body side under the belt, clear of the windows and wheel discs, and no gap line running through the shape itself. | Its outline (1.2 px simplified) as a closed groove 12 mm wide, 8 mm deep. carforge keeps 8 mm of paint between a flap's groove and a gap's; a flap drawn closer is moved along the car (up to 40 mm), then if needed shrunk about its centre (to 85 % at most), the least that clears; the evidence says by how much. |
| Grille opening (`recesses` with `bars`) | A region of dense ink full of tiny enclosed cells (≥ 12 % of the pixels around are cells of ≤ 12 px: the hatching), ≥ 10000 mm², its extents run out through the hatching to its outline; between the bumper's top and the belt, its centre within 2 px of the centre line, inside the body and not reaching past the headlamps. | Symmetric `x` (half its width), `z`, `radius` from the corner deficit, `depth` 20, cell black, `bars` every ~70 mm (count = width / 70 − 1), 22 mm wide, trim. |
| Headlamp / blinker (`lamps`, circle px) | Rings from `cv2.HoughCircles` and from round holes, refitted on the ink's distance map, inked round ≥ 95 % (cost ≤ 0.25), radius 25-200 mm; per centre the outermost such ring. A pair mirrored about the centre column (2 px), on one row (2 px), radii within 10 %, between the bumper's top and the belt, inside the body. The largest pair is `headlights`; one smaller pair (r < 0.75 of it) is `leftblinkers` (mirrored, so left and right). | The left ring as `circle`; headlamps `segments` 12, `dome` 30; blinkers `segments` 8. |
| Bonnet rib (`lines`, face top) | Thin level holes (raw ink: the one-pixel closing would fill a rib's 2 px inside), merged along a row across crossing lines (≤ 4 px), ≥ 300 mm long, ≤ 30 mm wide, ahead of the first window; a pair mirrored about the centre row (2 px) with the same ends (3 px). The centre rib (drawn solid on the centre line) is taken when the closed ink on the centre row is ≥ 4 px thick over ≥ 90 % of the pairs' span and ≤ 3 px behind it. | One line per pair (mirrored) and a `single` centre line, `width` = the rib's inside + 2 px (between its two drawn edges). |

Dropped, with the reason: lines that do not reach the sill (A-pillar and window-frame lines: "window k's frame" within 30 mm of a window edge, "ends at z=…"), lines that stop under the belt ("follows the front/rear arch" when an end is within 100 mm of the arch outline: the fender's lip lines), lines within 100 mm of the body's ends (corner lines), level lines running ≥ 40 % of the body (creases, mouldings, the roof line: gaps cross the side), boxes that are not boxes or sit on no gap or alone on their gap, panel strips bounded by long lines, handles without their partner, rings with no mirrored partner, below the bumper (chassis), above the belt or inside the grille's hatching, and closed shapes of no kind (with a note when the sheet's extras already give an item there, and "part of the … taken around it" for the inside of a taken handle or flap).

Style the drawing cannot give (proud, cells, radii, dome, groove width, bar pitch) is the hand-tuned look of `examples/uaz3151.json`, in the `*_STYLE` constants of `trace.py`.

Checks on the UAZ (render vs drawing, measured on the orthographic renders): door gaps' groove centres 2-5 mm (median, p90 ≤ 9 mm) from the drawn lines; handles, hinges (z, from where the plate hides the groove), blinkers, headlamps and grilles within 7 mm of the drawn outlines; flap within 5 mm (shrunk to 97 %, moved 1 mm); ribs within 6 mm along, 2 mm across. Arch width (render half-width minus drawn, car's left side): top view front arch median 29 → 0 mm (max 38 → 24), rear arch 24 → 0 mm (max 34 → 10); front view, arch rows z 560-900, median 34 → 10 mm (max 43 → 29; what is left is the hinges, 12 mm proud, and the top view drawing the body 5-15 mm wider than the front view does).

Generic assumptions (hold for any side/front/top line drawing): door and panel gaps are straight drawn lines (or chains of them) that cross the side from the belt or above down to the sill; hinges are boxes on a gap, at least two per gap; handles are small elongated closed outlines at belt height inside a door; flaps are rounded closed shapes of their own under the belt; lamps are well-inked circles in mirrored pairs; grilles are hatched closed shapes centred on the front centre line between the bumper and the belt; bonnet ribs are long thin closed outlines in mirrored pairs ahead of the windscreen. The size ranges are fractions of the wheelbase that fit cars (a door handle is 4-13 % of the wheelbase long); a microcar or a lorry may fall outside them, and is then dropped with "fits no detail kind", not invented.

What a drawing must give for the details: one line weight for body lines (the line width sets every tolerance; a sheet with thick outlines and hair-thin detail lines makes the detail tolerances too loose); a front view for lamps and grilles, a top view for ribs; a grille drawn as hatching or mesh (an open grille drawn as bars alone, without cells, is not found); lamps drawn as closed circles (≥ 95 % inked).

Known limits of the trace:

- Body side is a vertical wall below the shoulder in the schema, so the body under an arch can only be cut for the whole height. `plan.low` under an arch is therefore the drawn outline less the lip's flare, but never inside the body line bridged across the arch from either side: a deeper cut (the sheet's `flare` 30 against a drawn lip only `arch_drawn_proud_mm` proud, UAZ front 14, rear 19 mm) took the whole wing above the lip in and left a dent over each arch. The lip then stands its full `flare` proud of the door line, 11-16 mm prouder than drawn on the UAZ; set `extras.arches.*.flare` to the drawn proudness to match it exactly.
- Door gaps are taken from the belt down; a gap that runs on up a window frame (the UAZ front door's front edge up the A pillar) stops where its line crosses another one instead of ending in a corner. Door tops along the roof are level lines and are not taken.
- Only the side blinker, rear face and windscreen are still hand items on the UAZ sheet; a rear view is not traced.
- A hinge is a box drawn on its gap; one drawn beside a gap, or a door with one hinge, is dropped. Of several handle candidates only those with a partner on another door on the same row are taken.
- The GAZ-31029 preview is a valid trace baseline, but its filled preview makes bonnet, glass and
  pillar details coarse. The shipped GAZ therefore uses the trace for the silhouette and wheel
  geometry, then hand-refined `gaz31029.json` for those surfaces; `reduce.py` is not in that path.
- Grille bars are a fixed pitch over the opening, not the drawn mesh (the UAZ mesh is ~29 mm, too fine to model as bars).
- Front lamps are rings only; a rectangular lamp is not found.
- The body ends come from the extras bumper boxes when the drawing's bumper or spare would otherwise be taken as body; with no bumper in `extras` a full-width bumper in the top view counts as body.
- `side.bottom` in an overhang is mostly the bumper rule; between the wheels it needs a drawn sill line with a clear panel above it.
- An arch gap crossed by a mud flap or spring ends there; the run-out then follows the last slope, not the drawn fender (UAZ rear arch: opening 20 px short at the sill behind the wheel).
- Windows are quadrilaterals; a window with a cut corner or a curved edge loses it. A seat drawn against the upper half of a frame edge would still tilt that edge.
- The front view's own ground line sits 3-4 px above the side view's tyre bottoms on the UAZ scan (after deskew); `z0_px` comes from the side view and is used for both.
- Shoulder, belt and tumblehome are single values or one profile for the whole car (schema).

## FBX conventions

- Output is in metres: the spec's mm × 0.001 (Blender units ×1000 = mm).
- Axis: `axis_forward` −Z, up Y in the exported file; node rotation 0.
- Nose at −Y (spec frame), so the car faces −Y in the scene.
- Wheels named `wheel_fl`, `wheel_fr`, `wheel_bl`, `wheel_br` (use `--wheel-fbx` to export separately); the spare `<id>.spare`.
- Lamp objects named `<id>.body.<role>`; glass is atlas cell (3,1); lamp atlas cells: head (4,1) (the pack's grey lens: the white cell read as lit), tail (5,1), blinker (7,1), reverse (8,1).
- Atlas: 9 × 2 cells.

## Mesh fitting (`fit_mesh.py`)

1. Wheels: exactly four objects whose name contains "wheel". Lamps: objects tagged by `lamp_role`. Body: the rest.
2. Glass: atlas cell (3,1) in the packed texture, or material name matching `glass|window` for glTF.
3. Spec frame: y rearward from front-axle centre, z above wheel ground; x sign chosen so the front is at −y.
4. End trim (neither paint nor glass, outer 12% of length) grouped by connectivity: low wide groups reaching the end → `bumpers` (excluded from slicing), end-facing groups → `plates`.
5. 41 stations along y, 0.5% inside the ends, the end stations moved to the true ends. Shoulder is the largest 20 mm inward half-width step between 25% and 85% of height (else the belt), median-smoothed; on bonnet/boot slices `plan.high` is measured at the rail height; widths median-of-3.
6. Windows: each connected pane of left side glass (overlapping panes merged), outline = its hull in side view. `belt`/`glass_top`: medians of side glass z-min/z-max.
7. Windscreen/backlight: roof-slope glass (normal z > 0.2), envelope ± 60 mm.
8. Lamps → `single: true` boxes at their measured position. `fair_tol` 15.

Prints `FIT {...}` with length, width, height, wheelbase, track, belt, glass_top, window/bumper/plate counts.

## Known limits

- VAZ-2101 and BMW E46 ports are approximations: the old schema had no per-y body half-width, belt or glass top. Those values are estimates (noted in each file's `source`).

## Surface fairness (why the old bodies rippled)

Waves and accordion folds came from the station grid, not the trace:
- rows the station did not reach were pressed onto the roof line at a jump, so a row popped out
  between two stations and the quad between them folded (A/C pillars, bonnet edge);
- filler stations every 260 mm plus pixel noise in the trace gave many slightly twisted strips,
  and the game triangulates a twisted quad along an arbitrary diagonal → alternating creases;
- the belt lip faded in and out under the bonnet; face hint normals were tested before being computed.

Fixes: the ring is monotone (pressed rows move continuously, greenhouse rows stay on the
tumblehome), stations go exactly where a row emerges or the lip ends, no filler stations,
curves faired by `fair_tol`, every non-planar quad split along its convex diagonal.
`fairness.py` on the three examples: UAZ 18 folds / 59 ripples → 0 / 0; VAZ-2101 10 / 6 → 0 / 1
(one 2-6° bend pair at the C-pillar base); BMW 34 / 16 → 0 / 0.
